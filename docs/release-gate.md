# Release Gate

## Phase 0 결과에 따른 범위 조정

Phase 0 기술 스파이크 결과에 따라, 0.1의 Release Gate는 **Clipboard-first protection 경로**를 기준으로 적용한다. Direct typing(키보드+마우스 Send) 전체 경로에 대한 "보호 성공" 게이트는 0.1에 적용하지 않는다 — 이 경로는 애초에 보호됨으로 출시되지 않기 때문이다 (threat-model.md의 OPEN_QUESTION: SEND_INTERCEPTION_CAPABILITY 참고).

기존 감사 계약(✅ PRIVON 0.1 최종 감사 · 구현 계약) 15장의 Release Gate 조건들은 그대로 유효하며, 이 문서는 그 중 clipboard 경로에 해당하지 않는 항목의 적용 범위만 명확히 한다.

## 0.1 Release Gate 대상
- Clipboard 감지 → 치환 → read-back 검증 → 사용자 붙여넣기까지의 전체 흐름
- Clipboard 경로 기준의 Level 1~3 탐지 정확도
- 로그/telemetry에 clipboard 원문 미노출
- ChatGPT가 아닌 다른 앱 사용 중 clipboard 처리가 잘못 개입하지 않는지

## 0.1 Release Gate 비대상 (명시적 제외)
- Direct typing 후 Enter 또는 마우스 Send로 전송되는 경로의 "보호 성공" 검증 — 이 경로는 보호 대상이 아니므로 게이트가 성립하지 않는다.

# 0.4.0-beta Release Gate 적용 범위

> 이 섹션은 위의 0.1 내용과 독립적으로 추가된 0.4.0-beta 전용 섹션이다. 위의 0.1 Release Gate 내용과 기존 감사 계약 15장(§15)의 원본 조건은 변경하지 않는다.
> 이 섹션은 Controller가 승인한 제품 범위를 기록하는 문서 정리이다. **Release Gate PASS 선언, §15 조건의 면제, 릴리스 완료, 공개 배포 승인이 아니다.**

## 0.4.0-beta 확정된 제품 범위 (Controller 승인)

- 대상 플랫폼: Windows 11 x64
- Clipboard-first 개인정보 탐지, 그리고 지원된 경로에서의 치환 및 read-back 검증
- 미국 개인정보 탐지 13종
- 미국 기능은 P1 명시적 Opt-in 방식이며 기본값은 OFF
- 기존 한국 및 Global 보호는 유지

## 0.4.0-beta 비보장 기능

다음 항목은 0.4.0-beta의 제품 기능 범위에서 제외된다. 제품이 이를 보장하거나 제공한다고 주장하지 않는다.

- 직접 타이핑한 내용의 전송 차단
- Enter 키 및 마우스 Send 클릭 차단
- 실제 사용자 전송 이벤트 감지 보장
- 실험용 SendGuard X0
- 자동 업데이트
- 후속 국가 및 플랫폼 확장

이 항목들을 제품 범위에서 제외하는 것은 기능 범위의 결정일 뿐이다. 이와 관련된 미해결 기술 문제가 해결되었다는 선언이 아니며, 아래 "후속 개발 대상"의 OPEN 항목은 그대로 유지된다.

## 기존 §15 Release Gate의 적용 구분

0.4.0-beta에서 기존 §15 조건을 어떻게 다루는지 구분하여 기록한다. 이 구분은 적용 범위의 정리이며, 어떤 §15 조건도 이 문서에 의해 면제되거나 PASS 처리되지 않는다.

### #1 Send interception

- 0.4.0은 Clipboard-first 범위로 확정되었다. 따라서 직접 전송 차단의 성공을 제품 기능이라고 주장하지 않는다.
- 그러나 기존 §15 #1의 Phase 0 blocker는 **현재 OPEN** 상태이다.
- 기능 범위의 결정만으로 기존 출시 조건이 정식으로 면제되었다고 선언하지 않는다. 0.4.0에 대한 이 조건의 공식 적용 여부와 이를 판단하는 승인 권한은 별도로 확인해야 한다.

### #8~#9 Update / Rollback

- 자동 Updater는 이번 버전의 출고 기능이 아니다.
- 자동 업데이트 경로에 관한 조건을 적용 제외로 볼 수 있는지는 공식 판단이 필요하다. 이 문서는 그 판단을 대신하지 않는다.
- 수동 설치 및 업그레이드, 기존 저장소와 설정의 호환성, 복구 안전성은 검증되었다고 주장하지 않는다.

### #2~#7, #10~#12

- 제품에 실제로 적용되는 범위에서 그대로 유지한다.
- 기존 테스트 증거는 활용하되, 부족한 증거나 승인이 필요한 항목을 임의로 PASS 처리하지 않는다.

## 후속 개발 대상 (모두 OPEN)

| 항목 | 내용 | 상태 |
|---|---|---|
| A-1 | 전송 차단 | OPEN |
| O-3 | 원문 클립보드 잔존 | OPEN |
| Narrator | 접근성 제한 | OPEN |
| A2 | PID 재사용 | OPEN |
| R-1 | 활성화 확인 실패 시 미국 보호 중단 | OPEN |

Controller 결정에 따라 위 항목들을 단계적으로 개선하고, 1.0 정식 출시 이전에 해결하고 검증하는 것을 목표로 한다. 이 목표는 0.4.0-beta 공개 출시에 대한 위험을 자동으로 수용한다는 의미가 아니다.

## 여전히 공식 결정이 필요한 항목

- §15 #1(Send interception, Phase 0 blocker OPEN)을 0.4.0에 어떻게 적용할 것인지, 그리고 이를 결정하는 승인 권한
- §15 #8~#9(Update / Rollback) 중 자동 업데이트 경로 조건의 적용 제외 여부
- 수동 설치 및 업그레이드, 기존 저장소·설정 호환성, 복구 안전성에 대한 검증 증거와 판단
- 후속 개발 대상 OPEN 항목(A-1, O-3, Narrator, A2, R-1)을 0.4.0-beta 공개 출시 전에 어떻게 다룰 것인지
